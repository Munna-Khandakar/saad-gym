# SAAD GYM

A mobile-first, frontend-only workout tracker. There is no backend, no auth and no env vars. All state lives in the browser's `localStorage`. It deploys to Vercel with default settings.

## Commands

```bash
npm run dev      # dev server on :3000
npm run build    # production build (also regenerates route types)
npm run start    # serve the production build
npm run lint     # ESLint (includes React Compiler rules)
npx tsc --noEmit # type check
```

Before calling a change done, run `lint`, `tsc` and `build`, and make sure all three pass cleanly. There is no test runner in the repo.

## Stack

- **Next.js 16.4 (App Router, Turbopack), React 19.3, strict TypeScript.** This version differs from older Next.js. Read `node_modules/next/dist/docs/` before using an unfamiliar API (see AGENTS.md).
  - `cacheComponents` and `partialPrefetching` are enabled in `next.config.ts`. As a result, `dynamicParams` and other route segment configs are unavailable.
  - Reading `params` or `searchParams` must happen inside `<Suspense>`. Otherwise dev logs an "instant navigation" error. See `src/app/plan/[planId]/page.tsx` for the pattern.
  - `PageProps<"/route">` / `LayoutProps` are global types, and `params` is a Promise.
  - Route types are generated by `next build`. After adding a route, run a build before `tsc`.
  - Previously visited routes stay mounted but hidden (React Activity). Browser tests need `:visible` locators.
- **Tailwind CSS v4.** Tokens, keyframes and `--animate-*` utilities are defined in `src/app/globals.css` (`@theme`). `tw-animate-css` is installed.
- **shadcn/ui** (new-york, Radix) lives in `src/components/ui/`. Add components with `npx shadcn@latest add <name>`. `cn` comes from the `cn` npm package and is re-exported by `src/lib/utils.ts`.
- **Lucide** for icons. No other runtime dependencies. Confetti is pure CSS, so don't add animation or state libraries.

## Routes

| Route | Component | Content |
| --- | --- | --- |
| `/` | `HomeView` | Header, welcome line, 10-min warm-up checkbox (step 1), experience level picker (step 2), plan cards for that level (step 3) |
| `/plan/[planId]` | `PlanView` | Cycle tracker, day tabs, day progress, exercise checklist with weight logging |

Plan ids are slugs, `<level>-<n>` (e.g. `beginner-1`). `generateStaticParams` prerenders every plan in `WORKOUT_PLANS`, and any other id renders `notFound()`. `next.config.ts` redirects the old `/plan/1` and `/plan/2` URLs.

## Domain rules

- **Workout data is user-provided and must be entered exactly as given.** Don't rename exercises or reorder them. Sets and reps were removed at the user's request and are not shown; don't add them back unless asked.
- **Levels and plans:** `EXPERIENCE_LEVELS` holds Beginner, Intermediate and Advanced (Pro). Each plan in `WORKOUT_PLANS` has a `level` and a `number`. A plan with `days: []` renders as "Coming soon". Only Beginner Plan 1 has data for now.
- **Exercise ids** are stable slugs, used as storage keys for ticks and weights. Renaming one silently drops saved progress.
  - Beginner Plan 1 keeps its original `d1-…` ids. Give every new plan's ids a plan prefix (e.g. `b2-d1-…`, `i1-d1-…`, `a1-d1-…`) so they never collide.
- **Warm-up:** a single global item (`WARMUP_ITEM`, `dayId` 0) on the home page. It is the only item that expires, 4 hours after it is ticked (`EXPIRING_ITEM_IDS`).
- **Cycle:** exercise ticks persist until the user resets them. A day is done when all of its *required* items are ticked, and a cycle is complete when all 6 days are done, in any order.
  - Finishing the last day opens a celebration dialog. "Start new cycle" clears every plan item, keeps the warm-up, and returns to Day 1.
  - "Reset cycle" and "Reset Day N" both ask for confirmation.
- **Day 4 (recovery):** "Rest day done" is the only required item. Walking, Cycling and Battle Rope are `optional: true` and don't count towards progress.
- **Weights:** every exercise on a non-recovery day (`WEIGHT_ITEM_IDS`) can hold one weight in kg, the last one logged. It is edited by holding the row for 2 s (`HOLD_DURATION`) or tapping its `kg` button. Weights are never cleared by "Reset Day", "Reset cycle" or "Start new cycle".

## State and storage

- Keys. Changing a stored shape needs a new key version or a migration.
  - `saad-gym-workout-v1` holds `{ completions: [{ exerciseId, dayId, completedAt }] }`.
  - `saad-gym-weights-v1` holds `{ weights: [{ exerciseId, kg, updatedAt }] }`. `readWeights` validates it the same way (`0 < kg ≤ 999`).
  - `saad-gym-selected-day-v1` holds the selected day, and `saad-gym-selected-level-v1` holds the selected level.
- Only completions and weights are stored. Progress, "day done" and "cycle complete" are always derived and never persisted.
- `readCompletions` validates every entry: the id must be known, the `dayId` must match `ITEM_DAY_INDEX`, the timestamp must be finite and not in the future, and the entry must not be expired. It dedupes, then writes the cleaned list back. Corrupt data is cleared, not thrown.
- `useWorkoutProgress` is a module-level store read through `useSyncExternalStore`:
  - The server snapshot is `null`, so components render a skeleton until hydration. Keep it that way to avoid hydration mismatches.
  - It re-reads on a timer aimed at the next warm-up expiry, a 30s poll, `visibilitychange` / `focus` / `pageshow`, and the cross-tab `storage` event.
  - `Date.now()` is the source of truth. Timers only trigger re-checks.
- Wrap every `localStorage` access in try/catch, because private mode or blocked storage must not crash the app.

## Conventions

- Only add `"use client"` where it's needed: the views and interactive components. Pages stay server components.
- One-shot effects (confetti, the cycle dialog) fire only on a *transition* to complete. Use the "adjust state during render" pattern (`wasComplete` vs `isComplete`) rather than effects that set state, because the React Compiler lint rules reject those.
- Theme:
  - Dark only: background `#09090B`, cards `#18181B`, lime accent `#A3E635` (`primary`).
  - Rounded `2xl`/`3xl` cards and bold tracking-tight headings.
  - Use the theme tokens (`bg-card`, `text-primary`, `text-muted-foreground`, `border-border`) rather than raw colors.
  - Level colours: a `data-level` attribute re-themes its subtree by overriding `--primary`, `--ring`, `--level-soft`, `--level-deep` and `--level-gradient` (`globals.css`). Beginner is lime, Intermediate is a yellow-to-red blend (`#fb923c` solid), and Advanced is light red (`#f87171`). The home page wraps steps 2–3, and `PlanView` wraps the whole plan; the header and warm-up stay brand lime.
    - Keep using `primary` tokens, and use `bg-level-gradient` on larger fills. Never hard-code a level hex in a component.
    - Dialogs portal outside the wrapper, so put `data-level={useLevel()}` (`LevelTheme.tsx`) on their content.
- Mobile first:
  - Design for 375–390px wide.
  - Tap targets of at least 44px.
  - No horizontal page scroll; only the day-tab strip scrolls.
  - Respect `prefers-reduced-motion`.
- Accessibility:
  - Use real checkboxes with labels (the whole row is the label).
  - Day tabs are a `tablist` with arrow / Home / End key support.
  - Show lime `focus-visible` rings.
- Comments are sparse and explain *why*. Match the surrounding style.
- Keep the README in sync when behavior visible to the user changes.
